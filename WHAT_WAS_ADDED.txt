WHAT GETS TRACKED
═════════════════════════════════════════════════════════════════════════════

Every event records:

WHO:
  • Actor ID, DID, name, email, role
  • Hospital ID where action occurred
  
WHAT:
  • Module (admissions/prescriptions/certifications/operations)
  • Action (e.g., PATIENT_ADMITTED, PRESCRIPTION_UPDATED)
  • Entity ID and type (admission_id, rx_id, cert_id, bed_id)
  • Severity level (info/warning/critical)
  • Outcome (success/failure/unauthorized)
  
WHERE:
  • Hospital
  • Physical location (ward, room, etc.)
  
PREV/NEW:
  • Previous state (before change) - stored as JSON
  • New state (after change) - stored as JSON
  • Examples:
    - Admission: bed/ward/room changes
    - Prescription: diagnosis/notes/status/drug changes
    - Certification: name/status/expiry changes
    - Bed: status/patient_did changes
  
AUTH:
  • Authorization status (allowed/denied)
  • Authorization policy checked
  
CRYPTO:
  • record_hash - SHA-256(action|outcome|role|module|entity|hospital|timestamp)
  • anchor_id - FK to blockchain anchor
  • anchor_status - pending/anchored/failed

HOW IT WORKS
═════════════════════════════════════════════════════════════════════════════

Recording:
  1. User performs operation (admit patient, update prescription, etc.)
  2. Operation function calls tryWriteAudit() with audit builder
  3. Audit recorded in background (never blocks operation)
  4. SHA-256 hash computed over non-PHI fields
  5. Hash enqueued for blockchain anchoring
  6. Edge Function submits Solana transaction
  7. Signature + slot returned and stored

Verification:
  1. Admin clicks "Verify" on audit event
  2. verifyAuditRecord() called
  3. Postgres re-computes SHA-256 from stored fields
  4. Compares: recomputed_hash == stored_hash (DB integrity)
  5. Checks: solana_anchors record exists and is confirmed (blockchain integrity)
  6. Returns: verified status + both hashes + signature
  7. UI shows: tamper status + Solana explorer link

═════════════════════════════════════════════════════════════════════════════

✅ Tamper Detection
   SHA-256 hashing prevents undetected modifications
   Stored hash vs recomputed hash comparison

✅ Blockchain Anchoring
   Records anchored on Solana devnet (immutable)
   Signature + slot proves existence at specific time

✅ PHI Protection
   Only non-sensitive fields hashed
   Sensitive data stays in database
   HIPAA-compliant (no PHI on blockchain)

✅ Fire-and-Forget Auditing
   Audit writes never block primary operations
   Errors logged but don't propagate
   Users experience zero latency

✅ RLS Enforcement
   /admin/audit requires admin role
   Only admins see complete audit trail
   Role-based access at database layer

✅ Async Processing
   Blockchain anchoring happens in background
   Pending jobs tracked in audit_anchor_queue
   Admin can manually trigger processing
